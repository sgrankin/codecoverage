## Baseline tracking for non-main branches

- New `main_branch` input (default `main`) — the branch whose pushes store coverage baselines.
  Previously store-baseline mode only wrote git notes on pushes to a branch literally named `main`;
  now a `master` default branch or a long-running feature branch can track its own coverage history.
- Baselines remain namespaced per branch (`refs/notes/coverage/<branch>`), so PRs targeting the
  tracked branch compare against its baseline.
- Fixed: an explicit `mode: store-baseline` never stored anything (empty base branch on every
  non-PR event) — the documented scheduled-run use case was a silent no-op. A forced
  store-baseline now stores when the run's ref is the tracked branch, on any event.
